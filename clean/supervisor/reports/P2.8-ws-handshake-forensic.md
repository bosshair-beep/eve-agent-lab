## Verdict

P2.7’s in-container client **did reach** `ws://127.0.0.1:8000/xiaozhi/v1/` and the server **completed the WebSocket upgrade**, then **closed with 1000** in the same UTC second. No new INFO appeared because close happened in `WebSocketServer._handle_auth` **before** `ConnectionHandler.handle_connection` logs headers.

**One root cause (evidence permits):** runtime `server.auth.enabled=true` + HMAC token bound to `client_id|device_id|ts`. P2.7 reused the physical Device-Id and Bearer but minted a **new Client-Id**. Verify fails → send `认证失败` → `close()` (1000) → **no log line**.

Labels: OBSERVED / SOURCE_PROVEN / INFERRED / UNKNOWN as marked below.

## 2. Server path `/xiaozhi/v1/`

`websockets.serve` on `:8000` (`websocket_server.py:76-78`). **Path is not required to be `/xiaozhi/v1/`**; only `device-id` (header or query) is gated. Nginx `clean.eve.ai.vn` `location /xiaozhi/v1/` → host `127.0.0.1:18010` → container `:8000` is how the **physical** device arrives. P2.7 skipped nginx and hit `:8000` directly. That difference is **not** the silent-close mechanism (auth runs the same).

## 5. Protocol — was P2.7 an unsupported inject?

**No** (as designed). Direct raw text on this WS is **not** a user turn. Supported inject is `listen/state=detect/text=…` (same as device wakeup `"Sophia"`). Voice is `listen/start` + Opus + ASR; not required for detect-text.

P2.7 **used the supported inject** but **never sent it**. Failure is auth/handshake, not inject shape.

## 6. Root cause (single)

P2.7 **broke the auth triad**. Runtime auth is on. Token verifies `client_id` **and** `device_id`. New Client-Id + old Bearer → E4 silent 1000.
